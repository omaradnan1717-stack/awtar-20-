أوتار — اسم مستخدم وكلمة مرور + إنشاء موظف داخل الإعدادات

النسخة معدّلة، لكنها تحتاج تفعيل قاعدة البيانات والخادم مرة واحدة قبل الاستخدام.
لا يوجد حالياً مشروع Supabase مرتبط أو حساب مدير جاهز ضمن الملف.

الاستخدام بعد التفعيل:
- دخول باسم المستخدم وكلمة المرور فقط.
- حساب المدير > الإعدادات > إنشاء حساب موظف: الاسم، اسم المستخدم، كلمة المرور (12 حرفاً على الأقل).
- الموظف يسجل سحب مواد بالأسعار المحددة أو تسديداً ضمن الرصيد. لا يعدّل أو يحذف.
- المدير يضيف المواد والأسعار ويوقف حساب الموظف من الإعدادات.
- السحب يضاف إلى حساب دين قائم. إدارة كمية المخزون ليست ضمن هذه النسخة.
- التحديث بين الأجهزة بزر تحديث، والحفظ يحتاج الإنترنت.

خطوات التفعيل الأولي لمن يجهز الاستضافة:
1. أنشئ مشروع Supabase جديداً. نفّذ database.sql مرة واحدة.
   إذا كنت قد فعّلت الإصدار السابق فعلاً، شغّل upgrade_username.sql فقط بدلاً من database.sql.
2. أنشئ حساب المدير في Authentication > Users مع بريدك الحقيقي وكلمة مرور قوية، واجعله مؤكداً.
3. انسخ UID ونفّذ (ضع UID الحقيقي بدلاً من OWNER_UUID):
insert into public.awtar_users(user_id,role,name,username) values('OWNER_UUID','admin','عمر','omar');
   في حالة الترقية فقط، لا تكرر insert: ملف الترقية يحدد اسم المستخدم omar للمدير الحالي.
4. انشر الدالة supabase/functions/awtar-auth/index.ts باسم awtar-auth في Supabase Edge Functions.
   يجب تعطيل Verify JWT لهذه الدالة حتى يمر طلب تسجيل الدخول العام.
   الدالة نفسها تتحقق من JWT وصلاحية المدير قبل أي إنشاء حساب. لا تعطّل التحقق لدوال أخرى.
   باستخدام CLI: supabase functions deploy awtar-auth --no-verify-jwt
   تعتمد الدالة على SUPABASE_URL وSUPABASE_ANON_KEY وSUPABASE_SERVICE_ROLE_KEY المتاحة داخل بيئة الخادم فقط.
5. ضع Project URL والمفتاح العام publishable أو anon داخل config.js مكان null.
   هذه قيم عامة. لا تضع service_role أو sb_secret في ملفات الموقع نهائياً.
6. ارفع index.html وsecure.js وconfig.js معاً إلى نفس رابط الموقع القديم.
   لا ترفع SQL أو مصادر الدالة ضمن الملفات العامة؛ يتم نشر الدالة في Supabase فقط.
7. ادخل باسم المستخدم omar وكلمة المرور التي وضعتها لحساب المدير.
8. من الإعدادات استورد بيانات نفس المتصفح القديم، أو استخدم النسخ الاحتياطي لاستيراد JSON عندما تكون القاعدة المشتركة فارغة.
9. أنشئ الموظف من داخل إعدادات البرنامج، ثم أعطه رابط البرنامج واسم المستخدم وكلمة المرور بنفسك.

البيانات القديمة:
لا يمسح هذا التعديل بيانات Safari السابقة. استيرادها يحتاج نفس المتصفح ونفس رابط الموقع، أو ملف JSON.
تحتفظ الحركات السابقة بقيمها. لا تتم إعادة تسعير الديون القديمة.

ضوابط الحماية:
قاعدة البيانات تمنع الموظف من الوصول للإيرادات والمصروفات والسلف والمجهزين ومن تعديل أي سجل.
التسديد والسحب يتحقق منهما الخادم، وتثبت هوية الموظف وتاريخ بغداد تلقائياً.
أسعار المواد ثابتة من المدير. لتغيير السعر أوقف المادة ثم أضفها بالسعر الجديد.
سجل الرقابة مستقل ولا يسمح التطبيق بتعديله أو حذفه.
عند تعارض حفظ المدير مع عملية جديدة، يُرفض التغيير القديم ويطلب إعادة الإدخال بعد التحديث.
لا تشارك حساب المدير أو حساب إدارة Supabase أو GitHub مع الموظف.
أسماء المستخدمين 3–32 حرفاً إنكليزياً أو رقماً أو _ . - وتبدأ بحرف. لا تتأثر بحالة الأحرف.
حسابات الموظفين تُنشأ داخلياً دون بريد حقيقي؛ استعادة كلمة المرور بالبريد غير متاحة لهم في هذه النسخة.
إذا ضاعت كلمة مرور موظف، أوقف حسابه وأنشئ حساباً جديداً باسم مستخدم آخر.

التحقق:
فُحصت صياغة JavaScript ومسارات تسجيل الدخول ومنع إنشاء الحساب لغير المدير باختبارات محاكاة.
لم تُنفذ قواعد SQL أو الدالة على مشروع حي بعد؛ يلزم اختبار مدير وموظف بعد التفعيل وقبل تسجيل عمليات فعلية.
